# 团子 · 记忆系统与信息架构重设计（v2）

## 核心时间哲学：今日是工作台，过去是养料

> 用户视角：今天的一切都摊在桌面上（待办/卡片/记录/心情）；过了今天，桌面自动清空——但没有任何东西被扔掉，它们沉入手帐（记忆），需要时被检索、被 Agent 引用、被压缩成画像与笔记。

```
                    ┌────────── 今日（工作台）──────────┐
   录音/照片/文档 ──►│ 待办(今日) 卡片(今日) 时间线 心情 │
                    └──────────────┬───────────────────┘
                                   │ 日终归档 Agent（次日首启/当天最后一条完成时）
                                   ▼
        ┌────────────────────── 手帐（有机记忆）──────────────────────┐
        │ 画像(滚动重写)  课程笔记(滚动重写)  日结→周记(逐级压缩)        │
        │ 全部档案(转写/提炼原文, 全文检索)  待办历史(含过期)            │
        └────────────────────────┬───────────────────────────────────┘
                                 │ Agent 工具(检索/读取/写入)
                                 ▼
                          对话（Agent Runtime, P1方案）
```

## 一、记忆系统：日终归档 Agent（有机性所在）

现状问题：卡片当日失效已做，但**待办没有生命周期**、**过期内容去向是黑盒**、日结/周记是孤儿数据没有回流。

### 1.1 待办的有机流转（新增）

每条待办增加 `visibleFrom`（哪天开始出现在今日）：

| 日终归档时遇到 | Agent 决策（LLM，带上下文） | 去向 |
|---|---|---|
| 未完成、无截止 | 判断今天提过没有/是否还有意义 | **carry**（挪到今天）或 **drop-into-memory**（写入日结后从今日消失，仍可搜到） |
| 未完成、截止在未来 | 不动 | 到 due 日自动 resurface |
| 已完成 | 保持 | 进待办历史（可搜） |

今日页只显示 `visibleFrom ≤ 今天 ≤ (due 或 ∞)` 的待办。**用户看到的永远只有"今天该做的"。**

### 1.2 记忆分层（抄 Eta memory 的 core+headingIndex 思想）

| 层 | 内容 | 预算 | 用途 |
|---|---|---|---|
| L0 画像 | 滚动重写 | ≤120字 | 每次交互的常驻上下文 |
| L1 目录 | 课程笔记各课标题+字数、日结日期列表 | ~200字 | Agent 知道"有什么可查"，按需拉取 |
| L2 结构化记忆 | 课程笔记全文 / 日结 / 周记 | 按需读取 | read_course_note / get_dailies |
| L3 原始档案 | 全部转写/提炼 | 按需检索 | search_memory → read_transcript |

压缩链：原始档案 →(提炼)→ 日结 →(7天)→ 周记 →(语义)→ 画像。**任何一层都可回溯到原文**（引用角标）。

## 二、文档引擎：手帐 Tab（App 内一等公民）

现状问题：文档固化=导出到系统文件夹+App里只给个弹窗看文件名。用户要的是 **App 内完整的文档引擎**：查找、阅读、编辑都在 App 内完成；系统文件夹只是"告诉用户备份在哪"。

### 2.1 架构：store 是真相源，文件夹是镜像

```
手帐Tab(浏览/搜索/读/编) ──► store(真相源) ──自动同步──► 文档/团子/(用户可见备份)
```
不再"导出后从文件读回来"——所有阅读/编辑直接操作 store，写操作完成后静默同步到文件夹（复用现有 SAF 覆盖写）。

### 2.2 手帐 Tab 结构

```
┌─ 手帐 ──────────────────────────┐
│ 🔍 搜索全部记忆…                  │  ← 全文检索：转写/笔记/日结/待办历史
│ [全部] [课程] [画像] [日结] [档案]  │  ← 分区 chips
│ ─────────────────────────────── │
│ 👤 画像            120字 · 刚刚    │  ← 置顶卡片，点开可编辑
│ 📘 高等数学        笔记 · 昨天     │
│ 📘 心理学          笔记 · 2天前    │
│ 📅 今天            日结           │
│ 📄 遗忘曲线复习法   档案 · 10.7    │  ← 每条记录的转写+提炼
│ ...（虚拟列表，按时间倒序）        │
└─────────────────────────────────┘
```

### 2.3 全屏阅读器（替代现在的底部弹窗）

- **全屏页面**，不是 Sheet 弹窗
- Markdown 渲染 + 元信息（来源/时间/字数/同步状态）
- 操作栏：✏️ 编辑（画像/课程笔记可编，档案只读但可加笔记）/ 🔄 重新同步 / 💬 就此文档问 Agent（把文档注入对话上下文）
- 编辑器：全屏 TextArea + 保存 → 写回 store + 同步文件 + 更新 LLM 基准

### 2.4 与 Agent 的闭环
对话中的回答带引用角标 → 点击直接打开手帐阅读器定位到对应档案。手帐里任何文档可以一键"问团子"。

## 三、信息架构：6 Tab + 独立记录页 → 4 Tab + 中央录音键

现状问题：6 个底部 Tab 信息过载；"记录"独占一个 Tab 但核心只是一个按钮；卡片/搭子各自成页但内容稀薄。

### 3.1 新结构

```
┌──────────────────────────────────────┐
│              （页面内容）              │
│                                      │
│            ┌──────┐                  │
│            │  ⏺   │  ← 中央悬浮录音键 │
│            └──────┘                  │
│ ──────────────────────────────────── │
│  🏠 今日    📖 手帐    💬 对话    ⚙️ 我的│  ← 4 Tab
└──────────────────────────────────────┘
```

### 3.2 功能映射（一个不少）

| 现有 | 去向 |
|---|---|
| 今日(心情四态/时间线/日结) | **今日**：顶部心情四态 → 今日待办 → 今日卡片(横向滑动deck) → 今日时间线 |
| 搭子(待办) | **今日**的「今日待办」区块（当日可见项+快速添加） |
| 卡片 | **今日**的「今日卡片」区块：横向滑动卡组 + 点击进入全屏复习模式 |
| 记录(录音/拍照/文档) | **中央 ⏺ FAB**：单击录音；长按/上拉出菜单(📷拍照/🖼️相册/📄文档)。处理动态并入今日时间线（状态实时可见） |
| 问答 | **对话**（P1 Agent Runtime 落地处） |
| 课程笔记/日结/画像/已导出文件 | **手帐**（文档引擎） |
| AI配置/存储位置/清空/设备协同预留 | **我的** |

### 3.3 交互细节（丝滑感来源）

- **中央 FAB**：录音是一切入口，录制中变形为呼吸红键+计时，其他页面也常驻
- **今日卡片 deck**：横滑翻面，滑到底自动"今日复习完成"轻反馈；不做垂直长列表
- **待办**：左滑完成、长按维护，完成后淡出而非瞬间消失
- **手帐**：分区 chips + 搜索即时过滤（本地索引，0延迟）；文档卡片带同步状态小圆点
- **阅读器/编辑器全屏推入**（shared transition 的缩放感），返回手势自然
- Agent 对话：执行轨迹内联、引用角标、行动结果卡（P1方案）
- Tab 只有 4 个，标签大而清晰，拇指热区充分
