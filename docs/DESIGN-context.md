# 团子 · Agent 上下文构造规范（v2）

> 回答两个根本问题：上下文拼什么、为什么不会爆炸/被污染。

## 每次提问的上下文构成（自上而下）

| 层 | 内容 | 预算 | 说明 |
|---|---|---|---|
| ① system·人格 | AGENT_SYS 规则（查证/引用/CRUD/纠错） | ~600 字 | 固定 |
| ② system·常驻索引 | 画像(≤120字) + 课程笔记目录（只课名+字数） + 最近日结日期 | ~300 字 | 滚动重写，永不追加 |
| ③ 会话历史 | 最近 **6 轮** 问答（回答截 300 字） | ≤2200 字 | **多轮关联的来源**；超出轮次直接丢弃 |
| ④ 当前问题 | 用户这条输入 | — | |
| ⑤ 工具结果 | 每个工具结果截 **1500 字**，每轮 ≤8 次 | ≤12000 字 | 单次运行的临时上下文，不持久 |

**总计上限约 1.6 万字/轮**——DeepSeek 128K 窗口下永远安全，且这是一次性的（不累积）。

## 防污染：三层信息质量分级

核心原则（用户定稿）：**错误内容不配作为注入源**。

| 层级 | 内容 | 质量 | 是否进 Agent 上下文 |
|---|---|---|---|
| L2 提炼层 | extract 摘要/关键点/笔记/卡片 | ✅ 已纠错、已结构化（课堂/灵感双策略产出） | **默认注入**：search_memory 命中只给这层 |
| L1 原始层 | ASR 转写全文 | ⚠️ 口误/语气词/同音错字 | **仅显式读取**：read_transcript（用户要求看原文时） |
| L0 音频 | 录音文件 | — | 永不进上下文 |

search_memory 的匹配范围仍含原始转写（**搜得到**），但返回给 LLM 的片段取提炼层（**喂进去的是干净的**）——搜得出、吃不进噪音。

## 防爆炸：存储侧与上下文侧双轨

**存储侧（既有的记忆流转）**：
- 转写 14 天瘦身（留 300 字）→ 60 天深冷（只留摘要）
- 日结(7) → 周结(8) → 月结(6)，逐层压缩
- 卡片容量 30 张硬上限 + 已掌握降温

**上下文侧（本轮新增）**：
- 会话历史 6 轮硬上限（答 300 字）
- 单工具结果 1500 字
- 常驻索引（画像/目录）滚动重写不追加——使用两个月后的 system 长度和第一天一样

## 停止机制（本轮修复）

- 点「停止」→ 按钮立即变「停止中…」+ `AbortController.abort()` **掐断进行中的 LLM/网络请求**（此前只设标志位，要等当次请求自然返回才生效——表现为"没反应"）
- 300ms 轮询 + 每轮 turn/工具边界双保险检查
- 取消的回答显示「（已停止）」，不写错误
