# 团子 · Agent 上下文构造规范（v3 · Eta 对齐）

> v2 的「最近 6 轮 × 300 字」是拍脑袋，已废弃。v3 对齐 [Eta](https://github.com/Mangi-11/Eta) 的 Agent Runtime 设计
> （其核心又参考 Pi Coding Agent）；出处见 Eta `docs/AGENT_RUNTIME.md`。

## 每次提问的上下文构成

| 层 | 内容 | 预算机制 | 出处 |
|---|---|---|---|
| ① system·人格 | AGENT_SYS 规则 | 固定 | — |
| ② system·常驻索引 | 画像 + 课程目录 + 日结日期 | 滚动重写，永不追加 | — |
| ③ 会话摘要 | 会话压缩后的一段 assistant 历史（带说明） | 只在触发压缩后存在 | Eta：摘要作为带明确说明的 assistant 历史，不升格 system |
| ④ 会话历史 | **全量**未压缩轮次（user q + assistant a，不截断） | **不设轮数上限** | Eta：增量续接，全量 history |
| ⑤ 当前问题 | 用户这条输入 | — | — |
| ⑥ 工具结果 | 每个截 1500 字，单轮 ≤8 次 | 单次运行临时上下文 | — |

## 防爆炸：不是截断，是压缩（Eta 机制）

- **触发**：只看服务商**实际返回的 `usage.prompt_tokens`**（绝不估算），达窗口 85% 触发；窗口大小取设置项 `contextWindow`（默认 128K）
- **时机**：完整工具批次结束后的下一次请求前
- **执行**：摘要请求禁用工具；保留最近 4 轮原文，其余压缩为一段摘要；**只有完整且确实缩小的摘要才提交**——空/截断/失败一律保留原文（Eta：不降级）
- **原文永不丢**：session.messages 是 journal（完整历史），摘要只影响拼进模型的部分
- **兜底工具 `conversation_history`**：模型可分页回查会话被压缩前的原文（Eta 同款，弥补摘要有损性）

## 防污染：三层信息质量分级（不变）

| 层级 | 内容 | 进上下文？ |
|---|---|---|
| L2 提炼层 | 摘要/关键点/笔记/卡片（已纠错） | 默认注入（search_memory） |
| L1 原始层 | ASR 转写全文 | 仅 read_transcript 显式读取 |
| L0 音频 | 录音文件 | 永不 |

## 停止机制（不变）

AbortController 掐断进行中请求；按钮即时「停止中…」；取消显示「（已停止）」。
