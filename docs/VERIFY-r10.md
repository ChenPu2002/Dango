## 改动清单

### 1. 双场景录音（归属 = 用户主动选择，AI 只做内容处理）
- 点 FAB → 「开始记录」选择浮层：💡灵感闲聊（→ 待办/心情/画像事实，永不进课程） / 📖课堂录音（选已有课程 chips 或输入新课名）
- job 携带 `mode/course`；时间线标题带课程名；录音中胶囊显示 `📖高数 12:34` / `💡 12:34`
- 提示词双策略：`EXTRACT_SYS_CLASS`（卡片/分段提炼/课程笔记）与 `EXTRACT_SYS_CASUAL`（轻量：todos/mood/profile_facts/funs，**明确禁止 cards 与课程笔记**）
- MERGE 硬规则：`mode=casual 的材料 note 必须为空对象`

### 2. 转写纠错 = 纯提示词（无词典、无热词表）
- CLASS/CASUAL/SEGMENT 三处统一加入纠错原则：**以语境与常识推断（说话人身份/主题/通顺性），全字段统一正名；无把握保留原词，绝不臆造**
- 真机实证：用户口述「团子APP」曾被 ASR 转成「传子APP」并固化进待办；本轮整理后待办已显示「开发/推进**团子**APP」（旧档案标题为历史数据）

### 3. 存量「日常」分拣迁移（一次性，幂等）
- `migrateLegacyCasual()`：约定→待办、长期信息→画像事实，完成后删除「日常」键；空壳笔记直接清理；挂 `runArchivist` 开头（启动即跑）
- harness 断言：键删除 / 拿快递进待办 / 画像吸收学情 / 幂等不重复

### 4. 对话对齐 Eta
- 新工具 `web_search`（默认 DuckDuckGo HTML 零配置；「我的」页可配博查 Key 走国内可达通道）与 `web_fetch`（URL→正文抽取）——**不绑定单一搜索服务**（Eta 同款思路）
- 消息长按 → 重新生成 / 删除这轮（与发送共用 runOne 管线）
- AGENT_SYS：时效性/外部信息先 web_search 再 web_fetch，注明〔来源〕

### 5. 云文档重做（日期分组 + 类型筛选 + 照片可见）
- 数据源改为 jobs+记忆文件：**照片条目显示缩略图**（RN Image），点开全屏预览；转写/提炼/记忆各自条目
- 按日期分组（今天/昨天/M月D日）+ 类型 chips（全部/照片/转写/提炼/记忆，带计数）
- exporter：照片本体（jpg）进导出链路（base64 直写 SAF），外部文件夹也能看到拍的板书

### 6. 记忆分层自动运转机制（移动端无严格 cron，三重兜底）
1. **启动**：runArchivist（含迁移）→ 尾部接 nightlyMaintenance（补上此前无调用方的遗留 TODO）
2. **活跃期**：App 每 30 分钟检查，距上次维护 >20h 自动触发
3. **幂等标记**：lastNightlyAt / lastArchivistDay 保证不重复
- 分层卡显示「自动整理：启动时 + 使用中定期检查 · 上次 N 小时前」（状态可见）

### 7. 构建坑根治
- **此坑咬了两轮**：gradle 增量构建复用旧 JS bundle → 新代码静默不进 APK（真机表现「功能没做」）
- 根治：`android/app/build.gradle` 强制 `BundleReleaseJsAndAssets` 永不 up-to-date；STATUS 构建命令同步标注
